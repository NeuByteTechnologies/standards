# Repo Governance Standard: .gitignore Specification
**Version:** 1.0
**Owner:** NeuByte Standards Committee
**Applies To:** All NeuByte repositories
**Purpose:** Ensure consistent, noise‑free source control by defining technology‑specific ignore rules and a unified governance model.

## 1. Overview
Build artifacts, IDE metadata, caches, and temporary files **must never enter source control.**
This standard defines:

- A **global baseline ignore set**
- **Technology‑specific ignore modules**
- **A composition model** for repo maintainers
- Rules for **tracking vs. ignoring** generated files
- A **cleanup procedure** for repos already polluted with build artifacts

This ensures clean commits, predictable repo hygiene, and consistent behavior across all NeuByte projects.

## 2. Governance Model
Each repository must include a .gitignore file composed of:

  **1. Global baseline rules**
 **2. One or more technology modules,** depending on the repo’s code sets
**3. Optional project‑specific rules,** if justified and documented

## 5. Composition Rules for Repos
Each repo must include a .gitignore that imports the correct modules.

Example: fitness-web (Blazor + .NET + Web)
Code
# Global
!include standards/repo-governance/gitignore/global.gitignore

# .NET
!include standards/repo-governance/gitignore/dotnet.gitignore

# Blazor
!include standards/repo-governance/gitignore/blazor.gitignore

# Web
!include standards/repo-governance/gitignore/web.gitignore
Example: fitness-app-data (SQL + .NET)
Code
!include global.gitignore
!include dotnet.gitignore
!include sql.gitignore
Example: fitness-etl (Python + Data + .NET)
Code
!include global.gitignore
!include python.gitignore
!include data.gitignore
!include dotnet.gitignore

## 6. Cleanup Procedure for Polluted Repos
If build artifacts are already tracked:

Step 1 — Add correct .gitignore
Include global + modules.

Step 2 — Remove tracked build files
Code
git rm -r --cached .
git add .
git commit -m "Clean tracked build artifacts per repo-governance standard"
Step 3 — Verify clean working tree
Build the project and confirm no build artifacts appear in GitHub Desktop.

## 7. Rules for Project-Specific Exceptions
Exceptions must:

- Be documented in custom.gitignore
- Be approved by the standards committee
- Never allow build artifacts, IDE metadata, or caches

Valid exceptions include:

- Generated documentation that must be versioned
- Static assets produced by a build pipeline
- Schema files generated by SQL projects

## 8. Compliance Requirements
All NeuByte repos must:

- Use this governance model
- Include only approved modules
- Avoid committing build artifacts
- Pass quarterly repo hygiene audits
- Non-compliant repos will be flagged for remediation.

## 9. Versioning
This standard is versioned.
Changes require:

- Architectural review
- Standards committee approval
- Version bump
- Communication to all repo owners
